# 改进方案

## 概述
系统已从 **NRF24L01** 切换为 **树莓派蓝牙直控小车（JDY-31）**。日志中“树莓派检测过程中又收到 STM32 消息”的原因，是 **STM32 仍在执行旧的 NRF 自动停车触发逻辑**，导致二次 `MODE/ TRIGGER`。

## 日志对应结论
当实时距离下降到 `target_D + 30cm` 区间时，STM32 在 `App_HandlePiData()`（`#ifdef ENABLE_WIRELESS`）里会强制发送：
```
MODE:2
TRIGGER
```

## 改动清单（重点）

| 项 | 位置 | 问题 | 影响 | 建议 |
|---|---|---|---|---|
| 1 | `main.h` + `User\\main.c` | `ENABLE_WIRELESS` 仍开启，旧 NRF 自动停车逻辑触发 `MODE/ TRIGGER` | 树莓派测量过程中被 STM32 二次触发 | 关闭 `ENABLE_WIRELESS`，或加 **蓝牙模式开关** 并屏蔽 `App_HandlePiData()` 里的停车段与 `App_HandleWireless()` |
| 2 | `pro\\main.py` (`measurement_done`) | 完成一次测量后设为 `True`，新 `MODE:2~5` 不会再 `bt.send_go()` | 后续一键启动无响应 | 在收到新 `MODE:2~5` 或 `D=` 更新时重置 `measurement_done=False`，或改为只由 `car_running` 控制 |
| 3 | `pro\\main.py` (`MODE`/`D=` 时序) | 收到 `MODE:2~5` 立即发 `GO`，此时 `target_d` 可能还未更新 | 停车逻辑依赖旧/0 的 `target_d`，导致异常 | 仅在 `target_d>0` 时发 `GO`；或要求 **STM32 先发 `D=` 再发 `MODE:`**；或新增显式 `START` 指令 |
| 4 | `pro\\main.py` (`ENABLE_FLASK`) | 预览模式下使用 `_frame_worker`，**缺少蓝牙停车+触发测量逻辑** | 开预览时小车不会自动停/触发 | 抽出共享逻辑并在 `_frame_worker` 中复用，或运行时保持 `ENABLE_FLASK=False` |
| 5 | `pro\\main.py` `_send_mode_info()` + `Hardware\\Pi_Comm.c` | 模式3仅回 `D,x`，而 STM32 仍按“多正方形列表+STATUS”解析 | HMI 的编号列表更新不了，逻辑不一致 | 统一协议：要么树莓派发送多正方形+`STATUS`，要么 STM32 放宽 mode3 解析 |

## 建议执行顺序
1. **先关 `ENABLE_WIRELESS`**，避免 STM32 二次触发（解决你当前日志现象）。
2. 修复 **`measurement_done` 复位** 与 **`MODE/D` 时序**，保证一键启动稳定。
3. 根据是否需要预览，处理 **Flask 模式的蓝牙停车逻辑缺失**。
4. 统一 **mode3 协议**，避免显示与逻辑分叉。

## 已完成的修改（2026-05-22）
1. **关闭 NRF 旧逻辑**  
   - 文件：`main.h`  
   - 改动：注释 `#define ENABLE_WIRELESS`，避免 STM32 在测距过程中二次发 `MODE/ TRIGGER`。

2. **mode3 不带编号时清空 N 显示**  
   - 文件：`Hardware\\Pi_Comm.c`  
   - 改动：当收到 `D,x` 且无 `N` 时，清空 HMI 的 `N` 文本，避免残留旧编号。

3. **修复 MODE/D 顺序导致的误 GO**  
   - 文件：`pro\\main.py`（`_uart_listener()`）  
   - 改动：收到 `MODE:2~5` 不再立即 `GO`；新增 `awaiting_go` 标志，仅在收到 `D=` 后才发 `GO`，避免静止测量误启动车。

## 仍需处理（待接手）
1. **`measurement_done` 复位策略**  
   - 现状：测量完成后会阻止后续 `GO`。  
   - 建议：收到新的 `MODE:2~5` 或 `D=` 时重置，或改为仅用 `car_running` 判断。

2. **Flask 预览模式下缺少蓝牙停车/触发逻辑**  
   - 现状：`ENABLE_FLASK=True` 走 `_frame_worker`，不会执行停车与触发测量。  
   - 建议：抽出公共逻辑供 `_frame_worker` 复用，或运行时保持 `ENABLE_FLASK=False`。

3. **mode3 协议是否统一**  
   - 现状：树莓派只回 `D,x`，STM32 不再依赖 N 列表。  
   - 若未来需要“多正方形列表”，需恢复树莓派的 `send_multi_squares + STATUS`。
