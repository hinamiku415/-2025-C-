# 无线通信方案演进与架构设计：从 NRF24L01 到树莓派蓝牙直连

## 1. 方案演进背景与对比

在系统早期的初版设计中，运动目标小车由测量控制台（STM32）通过 2.4GHz NRF24L01 射频模块进行无线控制。但在实测调试过程中，该链路暴露出了多个严重的硬件资源冲突与闭环时延缺陷，最终系统全面重构并升级为 **树莓派蓝牙直控小车方案 (JDY-31 SPP)**。

### 1.1 方案对比总结

| 对比维度 | 第一代：STM32 + NRF24L01 (已废弃) | 第二代：树莓派 + JDY-31 蓝牙直连 (现行方案) |
| :--- | :--- | :--- |
| **控制拓扑** | 树莓派 -> (串口) -> STM32发射台 -> (NRF24L01) -> 小车 | **树莓派 -> (经典蓝牙 RFCOMM) -> 小车** |
| **闭环控制层级** | 双跳转发（树莓派测距判停需先报给STM32，再由STM32发无线） | **单跳直达**（树莓派视觉端测距达标后，直接向小车发 STOP 指令） |
| **引脚冲突风险** | **严重**：NRF 占用 SPI 引脚，曾与 USART2 树莓派通信脚冲突，被迫飞线 | **零冲突**：发射端彻底关闭 NRF，小车端占用独立的 UART4 (PC10/PC11) |
| **电源与干扰** | NRF24L01 瞬态发射电流大、易发烫，且高频杂波干扰自制 INA226 采样 | 树莓派板载原生蓝牙，无需额外射频发射板，彻底消除控制台射频干扰 |
| **刹停响应时延** | 约 100~200ms（视觉解算 + 串口中断 + NRF发包 + 小车收包） | **< 30ms**（树莓派视觉线程直接下发 `STOP`，制动精度极大提升） |
| **通信协议** | 自定义十六进制裸包 (`[0xAA][0xDD][0x01][0x00]`) | 简单明文 ASCII 协议 (`GO\r\n`, `STOP\r\n`, `TARGET:100\r\n`) |

## 2. 现行蓝牙通信实现规范 (JDY-31)

### 2.1 硬件连接
- **小车端主控**：STM32F103
- **蓝牙从机模块**：JDY-31 (经典蓝牙 2.1+EDR, SPP 协议)
- **硬件串口**：小车 **UART4**
  - JDY-31 TX -> STM32 **PC11** (UART4_RX)
  - JDY-31 RX <- STM32 **PC10** (UART4_TX)
  - 波特率：`9600 bps`（8-N-1）

### 2.2 树莓派软件驱动 (`bt_comm.py`)
树莓派通过 Linux 原生 `socket.AF_BLUETOOTH` 套接字直接建立 RFCOMM 通道，无需依赖操作系统的 `rfcomm bind` 映射：
- **目标设备 MAC**：`5C:F1:50:14:D6:02`
- **通道**：Channel 1
- **断线自动重连**：当检测到 Socket 异常断开时，发送线程自动触发重连机制。

### 2.3 指令映射集
| 树莓派下发指令 | 终止符 | 小车动作响应 |
| :--- | :--- | :--- |
| `GO` | `\r\n` | 小车启动灰度循迹前进（置位 `Car_state2 = 1`） |
| `STOP` | `\r\n` | 小车执行强力反转刹车（`SetPWM(-800, -800)` 持续 200ms 后归零），蜂鸣器鸣叫报警 |
| `TARGET:<dist>` | `\r\n` | 设定小车编码器运行目标距离（例如 `TARGET:100` 表示 100cm） |

## 3. 测量台发射端主控适配

在测量台发射端源码 (`02_Console_STM32/User/main.c` 和 `main.h`) 中：
1. **彻底关闭 NRF24L01 代码**：注释掉 `#define ENABLE_WIRELESS`；
2. **避免二次触发 Bug**：旧版 STM32 在检测到小车到达时会向树莓派二次发送 `MODE / TRIGGER`，关闭该宏后彻底消除了时序死锁现象；
3. **串口分配清爽化**：树莓派与 STM32 之间专心使用高速串口进行测量数据与模式调度，不再受 NRF 硬件引脚飞线的困扰。
