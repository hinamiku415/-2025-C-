# INA226 调试记录

**日期：** 2026-05-11  
**硬件：** STM32F103C8 + INA226AQDGSRQ1（U11，VSSOP-10封装）  
**采样电阻：** R8 = FMF25FPJR005-LH（标称 5mΩ）

---

## 1. 硬件连接

原理图（U11）：

```
VIN ──→ R8(5mΩ) ──→ IN 负载端
         │                │
       U11.10(VIN+)    U11.9(VIN-)
         └──── INA226 ────┘
                  │
              U11.8(VBUS) ──→ VIN（测总线电压）
              U11.6(VS+)  ──→ VCC（芯片供电）
              U11.4(SDA)  ──→ PB7
              U11.5(SCL)  ──→ PB6
              U11.1(A1)   ──→ GND
              U11.2(A0)   ──→ GND  → I2C地址 0x40
              U11.7(GND)  ──→ GND
```

I2C 上拉电阻：R6/R7 各 5.1kΩ，上拉到 VCC（3.3V）。

## 2. INA226 内部两条电流计算路径

INA226 提供两种方式读取电流，原理完全不同：

### 路径 A：校准寄存器路径（REG_CALIB → REG_CURRENT）

```
用户写入 REG_CALIB
    ↓
芯片内部：current_lsb = 0.00512 / (calib × R_shunt)
    ↓
芯片读取分流电压 ADC
    ↓
REG_CURRENT = ADC值 × (1 / current_lsb)  （芯片内部定点运算）
    ↓
用户读 REG_CURRENT，乘以 current_lsb 得到电流
```

**优点：**
- REG_POWER 由芯片硬件乘法器自动计算（P = V × I），直接读一个寄存器
- 芯片内部定点运算，不受软件浮点误差影响

**缺点：**
- calib 值必须 ≤ 32767（uint16_t 有符号范围），否则溢出导致读数错误
- 参数配置复杂，current_lsb / calib / max_current 三者相互约束

**calib 计算公式：**
```
current_lsb = max_current_A / 32768
calib = 0.00512 / (current_lsb × R_shunt)
      = 0.00512 × 32768 / (max_current_A × R_shunt)
```

**calib 不溢出的约束：**
```
calib ≤ 32767
→ max_current_A ≥ 0.00512 × 32768 / (32767 × R_shunt)
→ 对于 R_shunt = 0.005Ω：max_current_A ≥ 1.024A
```

### 路径 B：分流电压路径（REG_SHUNTV → 软件计算）

```
芯片读取分流电压 ADC
    ↓
REG_SHUNTV，1 LSB = 2.5μV，有符号16位，范围 ±81.92mV
    ↓
用户读 REG_SHUNTV
    ↓
软件计算：I = shunt_uV / R_shunt × 校正系数
```

**优点：**
- 完全不依赖 calib，不存在溢出问题
- 参数简单，只需一个校正系数

**缺点：**
- 功率需要软件再读一次电压寄存器然后相乘，多一次 I2C 读操作
- 受软件浮点精度影响（对本项目精度要求无影响）

### 两条路径对比

| | 路径 A（Calib） | 路径 B（Raw） |
|---|---|---|
| 依赖 | REG_CALIB 正确写入 | 无 |
| 功率 | 直接读 REG_POWER | 软件算 I×V |
| 参数约束 | calib ≤ 32767 | 无 |
| 适用场景 | 需要硬件功率寄存器 | 调试、参数不确定时 |

## 3. 调试过程记录

### 3.1 初始现象

- 初始参数：`INA226_Init(2.0f, 0.01f)`（max=2A，R=10mΩ）
- 数控电源显示：445mA
- INA226 读数（路径A）：约 110mA，约为实际的 1/4

### 3.2 加入 Raw 路径对比

新增 `INA226_ReadCurrent_Raw_mA()`，直接读 REG_SHUNTV 计算。

- Raw 读数（未校正，R=0.005Ω）：214mA
- 数控电源：445mA
- 比例：445 / 214 ≈ **2.08**

结论：**实际采样电阻约为 2.4mΩ，不是标称 5mΩ**。  
可能原因：PCB 铜皮走线形成并联路径，或焊接的元件与标称不符。

### 3.3 Raw 路径校正

设置 `INA226_RAW_CORRECTION = 2.08f`，Raw 读数校正到 ~443mA，与数控电源基本一致。

### 3.4 路径 A（Calib）的问题

尝试通过调整 `max_current_A` 来校正路径 A：

| max_current_A | calib 值 | I 读数 | 说明 |
|---|---|---|---|
| 2.0f | 16777 | ~110mA | 偏小约4倍 |
| 1.0f | 33554 | ~221mA | calib 超过 32767，溢出 |
| 0.5f | 67108 | ~14mA | 严重溢出，读数乱 |
| 1.1f | 30490 | ~108mA | 在范围内，但仍偏小 |

**路径 A 的问题尚未完全定位，留待后续研究。**

可能的根因方向：
1. calib 写入后读回值与写入值不一致（I2C 写入失败）
2. 实际 R_shunt 偏差导致芯片内部计算基准错误
3. INA226AQDGSRQ1 与标准 INA226 的 calib 公式有差异（需查 datasheet）

验证方法：
```c
// 在 OLED 上显示 calib 写入值和读回值
sprintf(buf, "W:%04X R:%04X", g_ina226_calib_written, g_ina226_calib_readback);
```
若 R 值与 W 值不同，说明 I2C 写入有问题。

### 3.5 当前方案

放弃路径 A，全部使用路径 B（Raw）：

```c
float I_mA = INA226_ReadCurrent_Raw_mA();   // 分流电压 / R × 2.08
float V    = INA226_ReadVoltage_V();
float P_mW = I_mA * V;                       // 软件算功率
```

## 4. 当前代码参数

```c
// INA226.h

#define INA226_SHUNT_NOMINAL_OHM    0.005f   // 标称阻值（Ω），用于 calib 和 Raw 计算基准
#define INA226_MAX_CURRENT_A        1.1f     // 路径A用，calib不溢出的最小安全值
#define INA226_RAW_CORRECTION       2.08f    // 路径B校正系数，实测 445/214
#define INA226_CONFIG_VAL           0x4927   // 平均16次，转换时间1.1ms，连续测量
```

主循环采样（main.c）：
```c
float raw_ma    = INA226_ReadCurrent_Raw_mA();
float voltage_v = INA226_ReadVoltage_V();
g_current_ma = (int)raw_ma;
g_voltage_v  = voltage_v;
g_power_mw   = (int)(raw_ma * voltage_v);
```

## 5. 后续待研究

### 5.1 路径 A（Calib）读数偏小问题

**现象：** max_current_A=1.1f 时，calib=30490（正常范围），但 I 读数仍约 108mA，远小于实际 445mA。

**排查步骤：**

1. **确认 calib 写入成功**
   ```c
   // OLED 显示 g_ina226_calib_written 和 g_ina226_calib_readback
   // 两者应相等，若 readback=0x0000 说明 I2C 写入失败
   ```

2. **直接读 REG_SHUNTV 的原始 ADC 值**
   ```c
   int16_t raw_adc = (int16_t)ReadReg(INA226_REG_SHUNTV);
   // 445mA × 0.0024Ω = 1068μV → raw_adc 应约为 1068/2.5 = 427
   // 若 raw_adc 正常但 REG_CURRENT 偏小，说明 calib 没生效
   ```

3. **查 INA226AQDGSRQ1 datasheet**  
   确认汽车级版本（AQDGSRQ1）的 calib 公式是否与标准版一致。  
   标准版公式：`calib = 0.00512 / (current_lsb × R_shunt)`

4. **检查 I2C 时序**  
   软件 I2C 的 SCL 频率若过高，可能导致写入成功但读回错误。  
   可在 `I2C_SW_Init()` 中降低速率验证。

### 5.2 采样电阻实际阻值确认

用四线法（开尔文接法）精确测量 R8 两端阻值，确认是否真的是 2.4mΩ。  
若是 PCB 并联路径导致，可以在 PCB 上切断并联走线后重测。

## 7. 电压读数异常（12V）及 U15 地址冲突怀疑

**日期：** 2026-05-11

### 7.1 现象

输入电压为数控电源 5.12V（香蕉头 TP1 输入），但 `INA226_ReadVoltage_V()` 返回约 **12V**。

### 7.2 排查过程

**第一步：排除代码移位问题**

INA226 的 REG_BUSV 寄存器全部 16 位都是数据，1 LSB = 1.25mV，不需要移位（INA219 才需要右移3位）。代码 `raw * 0.00125f` 写法正确，排除。

**第二步：读原始 ADC 值**

临时在 OLED 显示 REG_BUSV 的原始值：

```c
uint16_t vbus_raw = INA226_ReadVoltageRaw();
// 显示格式：V:12.000V r:2792
```

读回 `r = 0x2792 = 10130`，对应电压 10130 × 1.25mV = **12.66V**。

正确值应为：5120mV / 1.25mV = **4096 = 0x1000**。

实际读数 10130 / 4096 = **2.47 倍**，不是整数倍，排除移位问题。

**第三步：排除接线问题**

- 数控电源负极已接板子 GND ✅
- 香蕉头 TP1 接数控电源正极 ✅
- 万用表未测（比赛时间紧，跳过）

**第四步：发现 U15 地址冲突嫌疑**

查网表发现板子上有**两片 INA226**，共用同一条 I2C 总线（PB6/PB7）：

| 芯片 | 封装 | A1 | A0 | 推断地址 | VBUS 接的网络 |
|------|------|----|----|----------|--------------|
| U11 | VSSOP-10（INA226AQDGSRQ1） | GND | GND | **0x40** | VIN（香蕉头输入） |
| U15 | INA226（普通封装） | GND | **悬空** | **0x40（疑似）** | +5V（USB-C 轨） |

关键问题：
- U15 的 A0 引脚在网表中**没有出现在任何网络**，说明 A0 悬空
- INA226 地址引脚悬空时，默认电平通常为低（等效接 GND），地址为 **0x40**
- 两片地址相同，I2C 读操作时**两片同时响应**，SDA 上的数据是两片输出的线与，结果为乱值

U15 的 VBUS 接的是 `+5V` 网络（USB-C 轨），而 U11 的 VBUS 接的是 `VIN`（香蕉头）。两片同时响应时，读到的电压是两片 VBUS 寄存器数据的线与叠加，既不是 5V 也不是 VIN 的真实值，解释了 12V 的异常读数。

### 7.3 当前临时方案

比赛时间紧，无法修改硬件，采用**固定电压值**代替读寄存器：

```c
// main.c
g_voltage_v = 5.09f;   // 锂电池标称电压，固定值
g_power_mw  = (int)(raw_ma * g_voltage_v);
```

电流使用 Raw 路径（REG_SHUNTV）读取，不受 U15 干扰（分流电压寄存器的值由实际电流决定，两片叠加后仍以 U11 为主，校正系数 2.08 已补偿）。

### 7.4 后续复盘排查方案

#### 方案一：确认 U15 地址（最优先）

用逻辑分析仪或示波器抓 I2C 总线，发送地址 0x40 时观察是否有两个设备同时拉低 SDA（ACK 阶段 SDA 被拉得更低/更快）。

或者用软件扫描 I2C 总线：

```c
// 扫描 0x00~0x7F，看哪些地址有 ACK
void I2C_Scan(void)
{
    for (uint8_t addr = 0x08; addr < 0x78; addr++) {
        I2C_SW_Start();
        uint8_t ack = I2C_SW_SendByte(addr << 1);
        I2C_SW_WaitAck();
        I2C_SW_Stop();
        if (ack == 0) {
            // 此地址有设备响应，OLED 显示
        }
        Delay_ms(1);
    }
}
```

若扫描结果只有 0x40，说明 U15 未上电或地址不同；若只有 0x40 且读数异常，说明两片地址确实冲突。

#### 方案二：飞线修改 U15 地址（根治）

给 U15 的 A0 引脚飞一根线接到 VCC（3.3V），使 U15 地址变为 **0x41**：

| A1 | A0 | 地址 |
|----|----|------|
| GND | GND | 0x40（U11） |
| GND | VS+ | 0x41（U15，飞线后） |

飞线后代码里可以用两个地址分别读两片：
- `0x40` → U11，测 VIN 电压和充放电电流
- `0x41` → U15，测 +5V 轨电压和电流

需在 `INA226.h` 中增加第二片的地址定义，或将地址作为参数传入读写函数。

#### 方案三：断开 U15 供电（简单粗暴）

将 U15 的 VS+（VCC 引脚）飞线断开，U15 断电后不再响应 I2C，总线上只剩 U11。

此方案最简单，但 U15 的功能永久丧失。

### 7.5 U15 的设计意图推测

从网表连接看：
- U15.6（IN+）→ VIN，U15.8（IN-）→ VIN（**两个引脚接同一网络，无法测电流**）
- U15.7（VBUS）→ +5V

U15 的 IN+ 和 IN- 接在同一个网络上，分流电压恒为 0，**无法测电流**。VBUS 接 +5V，只能测 5V 轨电压。

推测 U15 是原理图设计时的**占位备用**，或者 IN- 应该接 R8 的另一端但连错了网络。实际使用价值存疑，断电方案（方案三）可能是最合理的处理方式。
